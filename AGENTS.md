# EarthReadyMXFinal Agent Guide

This repository is an iOS application packaged as a Swift Playgrounds App
Playground (`Package.swift` imports `AppleProductTypes`, which only resolves
inside Xcode/Swift Playgrounds tooling).

## Commands

- Build the app: `xcodebuild -scheme EarthReadyMXFinal -destination 'platform=iOS Simulator,name=<simulator>' build`
  (plain `swift build`/`swift test` at the repo root fail immediately with
  `no such module 'AppleProductTypes'`; that is expected for this package type,
  not a regression).
- Test the extracted core logic: `cd EarthReadyCore && swift test --enable-code-coverage`

## Stack notes

- Platform target: iOS 16
- The app package is centered on the `AppModule` executable target
- `Package.swift` is normally autogenerated by Swift Playgrounds/App Playgrounds
  tooling. It now has one hand-edited addition: a local package dependency on
  `EarthReadyCore` (see below). Re-running the Playgrounds packaging tool may
  overwrite this and require re-adding the dependency block.
- `EarthReadyCore/` is a plain, non-Playground SPM package living alongside the
  app. It holds the app's pure game logic and data (`GameState`,
  `ChecklistData`, `KitBuilderData`, `SeismicZoneData`,
  `AppearancePreference`) and has a real `.testTarget`, because App Playground
  packages cannot declare test targets themselves. The app target imports it
  as `import EarthReadyCore`.

## Rules

- Do not hand-edit autogenerated package metadata unless the task explicitly
  requires regenerating it through the proper tool. The `EarthReadyCore`
  dependency block in `Package.swift` is the one sanctioned exception; keep it
  if the file gets regenerated.
- Keep iOS-specific behavior explicit and narrowly scoped.
- Keep pure logic and data in `EarthReadyCore` testable: avoid reaching for
  `UserDefaults.standard` or other global state directly inside it; prefer
  injected dependencies (see `GameState.init(userDefaults:)`).
- Views and hardware-facing managers (haptics, sound, motion, speech) remain
  in the app target and are not covered by `swift test`; report that
  honestly instead of implying full app coverage.
